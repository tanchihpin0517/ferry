# 未來的改進

[English](future.md)

Ferry 以後可能做得更好的地方。這裡沒有一項已經排定或決定：哪一項要做時，先在 [docs/drafts/](../drafts/README.zh-TW.md) 寫草稿，在那裡決定。[概觀](overview.zh-TW.md#範圍僅限單向)說不做的，在那之前照舊。

## 跨次執行的大檔續傳

如同 rsync 的 `--partial`：傳到一半的大檔，下一次從斷掉的地方接著傳，而不是從頭再送。

- **為什麼。** 每個 host 只有一條 SSH 連線，斷了傳輸就失敗；重跑時，已經完成的檔案會跳過，但傳到一半的大檔要整個再送一次。檔案越大、連線越不穩，代價越高。
- **可以接在哪裡。** 大於一段的檔案，是一段一段送的，每段到了就對它的雜湊檢查，檔案的雜湊由各段的串起來；所以已經寫好、檢查過的段是知道的。
- **要先決定的。**
  - 寫到一半的檔案要不要有名稱，讓下一次找得到：檔案系統允許時，它在完成之前沒有名稱，否則用暫存名稱，失敗時刪掉。
  - 多大的檔案才續傳，而不是重送。
  - 已經寫好的段，串起來的雜湊要不要從磁碟讀回來重算一次才相信，還是照記下來的用。

## sparse 檔案

如同 rsync 的 `-S`：檔案裡的洞照樣是洞，而不是寫成零。整段都是洞的，就以洞送出，不帶任何 bytes；Destination 留出位置，不寫入。

## 大檔的粗粒度 delta

一個大檔只改了幾處時，只送改了的段：Destination 送出它那份檔案各段的雜湊，Source 對相同的段回「沿用」。比 rsync 的 rolling checksum 粗，只找得到留在原處的段；代價是 Destination 要讀一遍它那份來算雜湊，而不是收整個檔案。

## hardlink

如同 rsync 的 `-H`：在 Source 上是同一個檔案的幾個名稱，在 Destination 上也是同一個檔案，而不是幾份複本。
